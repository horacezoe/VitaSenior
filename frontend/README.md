# 银龄 · 小银龄前端

按用户提供的《前端开发计划》恢复开发的手机 H5。电脑也展示同一套手机页面，最大宽度 480px。老人端浅绿／浅蓝，家人端淡黄。代码基于后端 `1962400421450a9e099818e3095bc052cf5ded0d`；未修改后端公共文件。

## 安装与启动

本轮环境：Node 24.18.0、npm 11.16.0，Windows PowerShell。先按 `../backend/README.md` 配置并启动 FastAPI，再运行：

```powershell
cd D:\codes\VitaSenior\frontend
npm.cmd ci
Copy-Item .env.example .env.local
# .env.local 里的 BACKEND_URL 指向本机后端，默认 http://127.0.0.1:8000
npm.cmd run dev -- --port 5175 --strictPort
```

打开 `http://localhost:5175`。所有 `/api` 请求和媒体内容走同源代理，手机不需要直接访问电脑的 `127.0.0.1`。页面“设置与我的”的服务地址通常留空；直接连接其他后端时，它须允许该前端来源，HTTPS 页面也须连接 HTTPS 后端。

**模型密钥只放后端私有环境变量。** 前端不接收、保存或打包 MiMo key。提交的 `.env.example` 仅含代理地址和可选证书路径；`.env`、本地环境文件、证书、私钥、数据库、`node_modules` 和 `dist` 均不提交。

手机与电脑应在可互通网络中。局域网 HTTP 可查看页面和使用文字辅助，摄像头与麦克风需要浏览器认可的安全来源。团队已有可信 HTTPS 入口时优先使用它；也支持在 `.env.local` 设置 `DEV_TLS_CERT` 与 `DEV_TLS_KEY`，由 Vite 使用已准备好的可信证书。证书须涵盖手机访问的主机名／IP，并被手机信任。本轮没有安装系统根证书或绕过浏览器安全提示，也没有做实体手机验证。

若 Windows 安装时提示原生 `.node` 文件被占用，先停止本项目 Vite，再运行 `npm.cmd ci`。

## 可运行的流程

- 登录页选择本人或家人，获取后端验证码并真正登录；快捷演示也走相同鉴权。两个角色分别保存会话，当前角色按浏览器标签页保存。
- 新老人通过手动填写或明确标记的社区样例完成匹配、核对和建档。家人通过四位码预览身份后绑定，保留前导零和服务端有效期。
- 老人首页仅突出“和小银龄通话”，下沉健康辅助层，显示真实待处理通知和本机已核对的鸡蛋奖励。
- 通话使用实际摄像头预览、约可见页高 40% 的圆形头像和一个常驻挂断键。自动分句、完整单声道 PCM WAV、每句一张截图、串行提交、实际播报、播报后继续聆听；播放时不采集语句。摄像头不可用可继续语音；麦克风／安全来源不可用时显示恢复与文字辅助。
- 挂断、离页和进入后台会停采集／播放；挂断释放媒体轨道和音频上下文。进入后台后须明确恢复。原请求不确定时保留同一 turn、媒体与幂等键重试，不把重试当作新业务。
- 记录查询、新增、纠正、取消、日历日报、档案、用药计划、提醒和记忆均有实际接口。药品和时段从真实计划／任务选择，播放提醒不会产生服药记录。
- 家人可看进度、记录和需关心事项，发送预设关怀、新文字或自己的 PCM 留言。档案／计划／提醒维护走修改申请；家人没有直接改老人健康事实或代替老人决定的界面。
- 看到、接听、完整播报和处理分别上报。完整播报要求实际播放器 `ended`、完整时长且未静音；按服务端 `repeat_count` 播放。60 秒窗口仅显示服务端 `auto_apply_at`，时钟以响应 `meta.server_time` 校准。中断／文字降级不伪造回执或窗口。
- 设置提供大字、连接、角色切换、演示家庭查看及创建新家庭；不删除旧组数据库记录。

## 契约与代码入口

唯一接口源是 `../backend/contracts/openapi.json`。`npm.cmd run contracts` 生成 `src/api/schema.d.ts`；`contracts:check` 比对真实源文件及生成内容。生成文件带 SHA-256，不手改、不格式化。生成器支持当前契约的 ref／组合／nullable／enum／对象和数组，遇到不支持的结构会失败；不为绕过工具错误修改后端契约。

当前后端少量嵌套 `discriminator.mapping` 不符合部分第三方生成器预期，因此使用轻量本地生成器，类型由实际 `oneOf` 与 `const` 保留区分。该问题已登记，不复制第二套后端 schema。

- `src/api/`：统一 envelope、真实错误、鉴权、超时、同源媒体票据及写入去重。
- `src/state/`：角色会话、当前老人、前台 presence、20 秒刷新、奖励凭据；静态 context 与 provider 分开，避免开发热更新重新创建 context。
- `src/media/` 与 `public/audio/`：PCM、VAD、截图、单声道 WAV、单实例播放器和可重试语音回合。
- `src/pages/`：两端流程和辅助页；`src/components/`：无业务模拟结果的复用控件。
- `src/assets.ts` 与 `public/assets/README.md`：正式素材接入与缺口。
- `tests/`：编码、分句、录音暂停／回收、播放结束／中断、幂等、权限错误和奖励去重边界。

45 个 P0 操作由下列流程承接，**接入索引不代表每项均已做浏览器或真机验收**：

- `SYS01/SYS02`、`AUTH01/AUTH02/AUTH04`、`DEMO01`：session、登录、设置。
- `MEDIA01/MEDIA02/MEDIA03`、`AI01/AI02`、`AGENT01/AGENT02`：通话、文字辅助、家人录音、通知语音决定、播放器。
- `ONB01/ONB02`：首次建档。
- `BIND01/BIND02/BIND03/BIND04`：绑定及已绑定老人选择。
- `PROF01/PROF02`、`PLAN01/PLAN02/PLAN03`、`SET01/SET02`：档案、计划、提醒；家人写入改走 `CHANGE01`。
- `TASK01`、`REC01/REC02/REC03/REC04`：实际用药任务及记录维护。
- `DASH01/CAL01/REPORT01`：首页、健康面板、日历日报。
- `NOTI01/NOTI02/NOTI03/NOTI04`：前台 presence、待处理横幅、通知播放／处理和家人关怀。
- `CHANGE01/CHANGE02/CHANGE03/CHANGE04`：申请、进展、完整详情、本人决定。
- `MEM01/MEM02/MEM03`：带来源的记忆查看、本人纠正及删除。

## 奖励口径与待接能力

后端尚无奖励账本接口。当前持久化的是每个服务地址＋老人独立的、服务端确认过的唯一 `checkin_id` 凭据；来源为写入结果、当日后台核对和已查看的历史记录。排除演示 seed 与未成立记录，纠正、同餐替换及重试不重复增加数量。通话中不跳转；回首页再消费动画队列。减少动态效果时保留数量但省略飞行动画。

这不是跨设备、跨浏览器的权威累计余额，清除本地存储也无法恢复未重新核对的全部历史。撤销记录暂不自动扣回已获得奖励，待产品／后端给出账本规则。A 后续提供持久奖励流水后，应替换 `RewardLedger` 数据来源，复用篮子与队列展示。
