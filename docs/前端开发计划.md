# VitaSenior 前端方案：围绕小银龄的极简手机体验

日期：2026-10-31（Asia/Hong_Kong）。状态：按用户最新口述重写；前端编码已停止，本次只修改方案。

本方案替代此前的前端开发与排班参考。设计依据为用户最新口述和[项目书](../银龄老年健康助手计划.md)；接口实现依据为[当前后端接口技术文档](当前后端接口技术文档.md)、[字段字典](前端联调/接口参考.md)和[OpenAPI](前端联调/openapi.json)。附件 HTML 仅保留功能排查价值，不决定界面、美术或导航。

## 1. 先把产品理念放对位置

> 把复杂留给 AI，把简单还给老人，把安心送给子女，把时间还给医生。

老人日常使用的核心行为是与数字人交流：把饭菜、运动、用药以及自己的问题告诉它，由它理解、追问、复述、请本人确认，再完成记录或查询。前端应承接这种自然交流，让老人少找功能、少学规则、少按按钮。

因此，老人端的主体验是**与小银龄通话**。健康记录、日历、档案、计划等承接查看、核对和必要维护，属于辅助层。后端有多个接口，不意味着老人首页需要多个功能按钮，也不意味着每个接口都要对应一个页面。

**极简约束的是布局与操作复杂度，控件和视觉设计要精美。** 首页保留鸡蛋激励，以精心设计的静态素材和入篮动效给予完成反馈，让少量元素有清晰层次、良好质感和亲切感。

子女端的核心是**了解家人近况、送出关怀、协助维护**。它可以比老人端承载更多信息，但同样采用手机页面，围绕当前关心的一位老人组织内容。

本次产品仍为通用日常健康管理与家庭协同。疾病背景、记录完成度和医学风险评估分别对待，沿用项目已确定的业务边界。

## 3. 老人端：一个主入口，辅助功能下沉

### 3.1 首页

首页围绕“找到小银龄，开始交流，并看见日常积累”组织，首屏按以下层级承载内容：

1. 简短问候和小银龄形象区域，以用户提供的图片或中性占位图片呈现。
2. 一个清晰的主操作：与小银龄开始通话。
3. 家人留言/提醒入口；有待处理内容时，用真实通知形成常驻横幅。
4. 一个收敛的健康辅助入口，进入个人健康面板，再查看记录、日历和档案等。
5. 鸡蛋激励展示：篮子贴图、清楚易读的鸡蛋数量，以及打卡成功后的鸡蛋入篮动画。

以上是信息层级，不要求五块同等大小的卡片。主操作应明显，辅助入口安静、容易辨认；鸡蛋与篮子是自然融入首页的激励元素，不额外增加一个必须点开的功能模块。篮子保持稳定、可辨识的位置，兼作动画终点；无通知时不制造提醒数量。

首页不陈列每个录入表单、接口能力、供应商状态或独立工具按钮。模拟模式用简短标识如实说明，连接设置、演示家庭管理和切换角色等放在辅助位置，避免成为老人日常操作的一部分。

### 3.2 与小银龄的视频对话页

这页采用通话式视觉结构。用户明确确定的三个常驻核心元素为：

- 摄像头实时预览，作为主画面。
- 小银龄圆形头像，顶部居中，直径约为屏幕高度的 2/5。
- 底部清晰、易按的挂断控件。

布局关系示意如下，仅表示位置与比例，不是美术稿：

```text
┌────────── 手机可见对话页 ──────────┐
│                                   │
│          小银龄圆形头像            │
│          顶部居中                 │
│          直径约 0.4 × H            │
│                                   │
│      摄像头实时预览作为主画面       │
│                                   │
│                                   │
│             挂断电话              │
└───────────────────────────────────┘
H = 当前手机可见对话页的高度
```

例如可见页高为 800 个逻辑像素时，头像直径目标约为 320 个逻辑像素。实际适配考虑安全区和横向可用空间，保持顶部居中与显著头像占比。

对话页以实时预览和状态图片承载“正在交流”的感觉，不采用消息列表加工具侧栏的聊天工作台。录音开始/停止、上传、发送、多个场景按钮等不作为常驻工具栏。

当前轮次确有需要时，可以短暂显示一句易读的状态提示、识别内容或待核对摘要。它们用于帮助理解当下发生的事，不把历史消息铺满主画面。涉及业务写入时仍必须让老人明确确认，不能为了减少按钮而省略确认。

### 3.3 免手动对话循环

目标交互按以下顺序定义：

1. 老人从首页主动进入对话，首次按浏览器要求授权摄像头和麦克风。
2. 页面显示实时摄像头预览，开始聆听；小银龄显示聆听状态图片。
3. 老人说完一句，前端自动判断句末，整理这句话的音频，并在句末获取一帧画面。
4. 提交当前轮输入，小银龄切换为思考状态；页面保留预览，不要求老人再按发送。
5. 返回回复后播放语音，切换播报状态；需要确认时先复述待保存内容，听取老人明确回答。
6. 本轮播报结束后自动继续聆听下一句，延续同一会话。
7. 老人点击挂断，结束当前交互并回到首页。

说话轮次与播报轮次应有清楚边界，避免把小银龄自己的播报再次识别为老人输入。自动断句、句末取帧、回复播放和再次聆听要作为完整链路验收，不能以单个录音文件上传成功代替。

挂断时停止摄像头、麦克风、当前录音和本地播放，停止后续自动提交。已经由后端保存成功的记录保持真实结果；尚未确认的候选不能因挂断而自动保存。

遇到权限拒绝、未听清、网络超时或无可用音频时，给出短句提示并如实降级。需要文字/表单辅助时进入辅助路径，不把通话主屏变成设备调试面板。

### 3.4 由同一通话入口承接的日常场景

| 老人的自然表达或行为 | 小银龄承接的流程 |
| --- | --- |
| 做菜前给它看食材、问怎么搭配 | 句末画面与语音理解食材，给粗粒度搭配建议；不自动保存为已吃的餐食 |
| 做好饭后给它看菜，说这是午餐 | 理解食物种类与餐次，复述待记录内容，明确确认后保存 |
| 说自己散步了多久 | 提取运动和时长，请本人确认后记录 |
| 回应服药提醒，说明实际情况 | 对齐既定计划和具体任务；模糊时追问，明确确认后记录 taken 或 not_taken |
| 问今天记录了什么、想看日报 | 读取现有事实，语音回复；需要细看时进入辅助详情 |
| 表达偏好或纠正习惯 | 按来源与记忆规则处理，允许之后查看、纠正和删除 |
| 请求绑定家人 | 通过既有能力生成绑定码，醒目展示并尽可能播报 |
| 拒绝家人提出的修改 | 对齐当前提案，明确执行拒绝；不把普通提醒的关闭当作拒绝提案 |

复杂或无法可靠理解的表达保留辅助维护路径。所有场景围绕同一个交互入口组织，不增加一排场景启动按钮。

### 3.5 健康辅助层

从健康辅助入口进入后，再按老人当前目的展示：

- **个人健康面板**：已确认的基本信息、饮食/运动/用药记录进度和必要推荐。
- **今日与历史记录**：看清记录内容；需要时纠正、取消或补充，三类记录保留各自业务语义。
- **健康日历与日报**：选择日期，查看当天记录和摘要；颜色表示记录进度。
- **档案、用药与提醒维护**：由本人核对后修改；复杂表单集中在相应详情页。
- **长期记忆**：查看小银龄记住的内容、来源与更新时间，支持本人纠正或删除。
- **家庭绑定与设置**：绑定码、语音提醒等必要设置，集中收纳。

辅助页按需进入和返回，不把所有编辑表单同时铺开。已有接口逻辑是否可复用，等方案确定并恢复开发后再检查；当前界面不作为最终页面结构。

### 3.6 首页鸡蛋激励与入篮动画

鸡蛋激励属于本轮首页体验，按用户最新要求保留。项目书历史材料中将其弱化为可选的表述，以本轮明确口述为准。

**奖励成立条件**：每次新的有效打卡成功保存后奖励 1 枚。先有明确确认和真实保存结果，再产生激励反馈；照片上传、识别候选、听完提醒或请求尚未成功都不发奖。纠正、同餐替换以及同次请求重试/幂等重放不重复奖励。取消已获奖记录等边界的奖励回收口径仍需明确，不在方案中自行设定扣回规则。

**动画按用户描述实现**：

1. 首页展示静态篮子贴图，接收位置与素材构图对齐。
2. 新奖励需要展示时，鸡蛋静态素材出现在页面的反馈起点。
3. 同一张鸡蛋素材向篮子移动，并沿途逐渐缩小，形成掉落、收进篮子的视觉反馈。
4. 素材抵达篮子的接收位置后，结束本次动画，以数量更新或简短正向文案完成反馈。

鸡蛋的运动路径、大小变化、节奏和篮子遮挡关系在手机预览中打磨；当前不写死起点坐标和动画时长。动画自动发生，不要求老人再按一次领取，也不增加领奖页或多步操作。

**跨页面时机**：

- 在与小银龄通话时完成打卡，继续当前对话，保留待展示的奖励反馈。
- 老人返回首页后，再播放鸡蛋移动、缩小并进入篮子的动画；不为播放激励自动结束通话。
- 同一奖励只播放一次；多次真实打卡产生多个奖励时，有序呈现，避免素材重叠和数字重复增加。
- 首页动画与健康记录保存、子女端同步分别处理，动画结束与否不改变记录是否已成功保存。

当前后端契约没有独立鸡蛋奖励账本或余额字段。恢复开发时，需要明确鸡蛋数量从有效记录推导还是补充持久化契约，并处理奖励去重与待播状态；不能用随意递增的页面数字冒充真实累计余额。这一工程缺口不改变本轮已经确定的首页展示与动画要求。

动画验收包括：只在真实成功后触发；纠正、重试不重复发奖；通话不被打断；返回首页后正常入篮；手机尺寸变化时终点仍对准篮子；动画不遮挡主要操作；用户开启减少动态效果时保留可理解的奖励反馈。

## 4. 家人提醒与提案：独立于日常 AI 对话的流程

### 4.1 亲情提醒

子女发出的预设关怀或本人录音形成应用内通知。老人进入应用且确实看到时，显示常驻横幅；有音频时提示接听。

老人接听后进入对应的模拟通话体验，播放真实录音或预设/合成音频，按要求完整播放指定次数后结束播报并同步状态。它与和小银龄自由交流的摄像头对话有不同目的，不把它们混成一套消息工作台。

同一时间只处理一条正在播放的内容，避免 AI 回复与家人留言重叠。正在与小银龄交流时，新关怀保留待处理提示，不能擅自替老人接听或伪造播放完成。

### 4.2 子女代维护修改

1. 子女调整档案、计划或提醒设置时，先提交提案，原对象保持原值。
2. 老人端通过横幅和应用内来电了解修改，完整播报内容及拒绝方式。
3. 未进入应用、未接听、未完整播报时，保持待通知，不显示已经开始的 60 秒窗口。
4. 服务端确认完整播报达到要求后，才展示 60 秒决定窗口。
5. 老人明确接受立即生效；明确拒绝终止修改；到期结果由后端决定并查询确认。
6. 版本变化、绑定撤销等引起冲突时，提示重新核对，不能自动覆盖。

拒绝入口在该决定情境下醒目呈现，语音拒绝仍须可用。这是当前提案的必要操作，不扩展成老人首页的常驻按钮集合。

## 5. 子女端：手机中的家人健康看板

子女端采用淡黄色主题，与老人端区分。信息密度可以略高，但按手机纵向阅读和单项任务操作组织。

| 层级 | 主要内容与操作 |
| --- | --- |
| 登录与绑定 | 手机号及演示验证码；输入四位绑定码、预览老人身份、选择关系并确认 |
| 家人总览 | 当前老人姓名、年龄、已确认疾病等有来源的信息；绑定多位老人时可切换 |
| 今日近况 | 三类记录进度、已记录内容和可解释的待关注事项；不要求先进入多个工具模块 |
| 送出关怀 | 在相关事项上直接发预设提醒，或通过录音发送自己的声音；支持核对接听与处理进度 |
| 日历与日报 | 在日期维度查看同一套真实记录和摘要，与老人端同步 |
| 协助维护 | 进入相关档案或计划详情提出修改，查看修改前后和提案状态 |
| 进一步查看 | 按需看三类记录、长期记忆和必要详情；子女不代老人打卡或决定提案 |

关注事项按实际记录表述，例如“暂无午餐记录”，不直接断言老人没吃饭或没服药。当前未配置风险评估、没有结构化身体数据或未实现的精确营养/药物冲突功能，按现有业务边界处理。

子女端的具体导航形式在手机线框中再验证，不先规定多标签栏、侧栏或桌面卡片布局。设计验收先看“能否很快了解家人、送出关心、找到提案”，而不是看界面展示了多少模块。

## 6. 数字人图片与其他素材清单

小银龄角色由用户提供。正式素材到位前，只使用没有脸部、身体或人格造型的中性占位图片，并标明素材缺失；不自行创造替代数字人。

| 素材 | 使用位置 | 状态与接入规则 |
| --- | --- | --- |
| 小银龄待机图片 | 首页、对话等待状态 | 待提供；使用中性占位 |
| 小银龄聆听图片 | 正在采集老人语音 | 待提供；随真实交互状态切换 |

头像容器为圆形，采用统一的图片映射表管理不同状态。正式图片到位后替换素材映射，保留角色本来的比例和构图，不擅自改画风。等待、聆听、思考、播报和异常的切换依据实际状态，不把静态图伪装成已实现的复杂数字人动画。

本方案不冻结具体色值、字体、阴影或正式美术素材。已确定的是两端的色彩方向、手机交互结构与精美设计要求，视觉细节在后续设计中完整落实。

### 6.1 精美控件与极简操作同时验收

- **排版与留白**：文字大小、字重、行距、对齐和区块间距有清晰层级；简短内容也要经过构图，主次关系一眼可懂。
- **控件质感**：主操作、辅助入口、挂断控件和状态反馈形成一致的形状、图标与交互语言，打磨按下、等待、成功和不可用状态。
- **色彩与易读**：老人端的浅蓝浅绿、子女端的淡黄色体现在整体主题中；文字和主要操作仍保持清楚的对比，避免浅色叠浅色难以辨认。
- **素材融合**：用户提供的小银龄图片、鸡蛋与篮子在比例、边缘、位置和视觉重量上协调；占位用于明确待补资源，不作为正式视觉完成度。
- **动效节奏**：鸡蛋位移与缩放流畅，入篮落点准确，奖励反馈清晰；动效服务完成感，不让老人额外操作或等待。
- **手机完成度**：以真实手机首屏和触控体验验收，包括安全区、大字、长内容和不同尺寸适配；少量元素同样需要完整设计。

## 7. 现有后端如何支撑这套体验

前端体验以“通话”和“日常关怀”组织，工程上继续复用现有 FastAPI + SQLite、媒体和 Agent 契约。下列约束解释可实现边界，不作为老人界面的常驻技术信息。

### 7.1 实时预览与逐轮处理

- 摄像头画面在手机端连续预览；当前后端通过一轮音频和句末的一帧图片进行处理。
- 当前 Agent 为同步 HTTP 轮次，没有视频流或全双工音视频通道。前端呈现通话体验，不声称后端在持续观看或分析完整视频。
- 自动断句、句末取帧、播报结束后继续聆听属于本次前端需要补齐并实际验证的能力，之前的手动录音与发送页面不等于它们已经实现。
- 保持同一会话，轮次串行，网络重试复用原轮次与幂等标识。模型和语音的延迟通过当前状态解释，不让老人重复按发送。
- 当前真实 ASR 接收完整 PCM WAV，不能将浏览器 WebM 只改后缀。采集编码与自动分段一起验证。
- mock ASR 只识别精确样例。受控 mock 联调与新录音的真实识别分别记录，不能用固定样例替代实际自由对话验收。

### 7.2 保留业务事实与权限

- 拍到饭菜、生成候选和听完回复都不等于保存记录；写入须明确确认。
- 未打卡只表示缺少记录；提醒处理状态与服药事实分开。
- 长期记忆保留来源，不覆盖已确认档案，不擅自新增疾病或药量。
- 绑定、记录、提案、看板等复用已有权限、版本和幂等规则；两角色、不同家庭会话与数据隔离。
- 提案倒计时以服务端 auto_apply_at 和 server_time 展示，播放中断、静音失败或无音频均不冒充完整播报。
- 手机 HTTPS、摄像头/麦克风权限、自动播放和现场网络必须真机验证。

## 8. 恢复开发时的顺序与验收

当前人员条件仍按 1 位前端、此前提出的两端全部 P0 目标记录。之前的 4–5 小时是当时的剩余时间估计，已发生的开发和返工计入消耗；此处不重新获得一个 5 小时窗口。恢复开发时应按实际剩余时间重估，不承诺全部 P0 在未知剩余工时内完成。

| 顺序 | 要形成的结果 | 验收重点 |
| --- | --- | --- |
| 1. 手机页面关系 | 老人首页、视频对话、健康辅助层、子女看板的低保真结构 | 首屏层级、入口数量、主次关系符合本方案；先看手机，不先做宽屏工作台 |
| 2. 三元素对话主屏 | 主摄像头预览、顶部居中圆形状态头像、挂断 | 头像直径约 0.4H；使用用户图片映射或中性占位；常驻操作只有挂断 |
| 3. 自动对话一整轮 | 进入聆听、自动句末、取帧、处理、播报、继续聆听 | 连续多轮无需反复开始录音或发送；小银龄不把自己的播报当输入；挂断真正释放设备 |
| 4. 饮食确认与两端同步 | 老人给它看饭菜并说明餐次，明确确认，子女看到同条记录 | 候选不提前写入；取消不写入；双端使用同一事实 |
| 4a. 鸡蛋激励闭环 | 新有效打卡奖励 1 枚，鸡蛋静态图移动、缩小至首页篮子贴图 | 纠正和重试不重复奖励；通话继续，回首页再播放；入篮落点与数量反馈正确 |
| 5. 亲情提醒与提案 | 子女发关怀/修改，老人收到并接听、决定，子女看到进展 | 真实播放回执；未完整播报不计时；拒绝醒目可用 |
| 6. 辅助功能补齐 | 记录纠正、计划、设置、日历日报、记忆和绑定等 P0 | 功能完整但不抬升成老人首页的大量入口 |
| 7. 真机与交接 | 手机实际流程、资源、网络和演示脚本 | 区分已实现、已通过、未通过、缺素材；不以桌面浏览器成功替代手机验收 |

视觉验收同步检查控件与设计是否精美，不能仅以入口数量少、功能可点击或占位图齐全判定首页完成。

两个已安装的设计技能用于执行阶段：frontend-design 协助独立视觉实现，web-design-guidelines 检查易读、标签、焦点、缩放和触控。它们不能改变本方案已经确定的产品理念和页面结构。
