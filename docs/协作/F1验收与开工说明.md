## 3. 实际具备的基础与限制

- SYS01/SYS02/AUTH01/AUTH02/AUTH04 已实现，其他40个P0为受权限和schema约束的501占位。
- 18张表、Actor/Access、UoW、Clock、幂等、Pydantic schema、typed ports和ServiceBundle均已存在。
- application 的三个领域文件只有 unavailable 入口；不能把它们当已实现的业务flow。
- 路由的 Context 来自 public_context：非GET请求会立即BEGIN IMMEDIATE。因此AI慢调用必须换成“短读鉴权→释放连接→模型→短写复核”流程，不能直接在现有ctx.tx里等待供应商。
- tests/framework 含有F0特有的“全部业务返回501、只五项能力为true、默认业务port未实现”断言。业务完成后这些断言不再是持续验收标准，需由A0分类，保留真实权限、回滚、幂等、schema等长期检查。
- MEDIA03目前仍要求Bearer，尚不支持文档约定的仅ticket播放；MediaPort也只有get_asset。A负责补齐，不让C自行另造媒体库。
- 部分跨域入口尚未定义，例如读取待服药任务、语音拒绝提案、生成音频登记。A0统一补齐后冻结，B/C不得各自猜签名。

## 5. A0必须统一的适配

1. 框架测试分清阶段：保留F0占位检查为明确的snapshot/marker用例，默认业务持续检查不要求已实现接口继续501。保留并补全真实授权、会话、rollback、唯一约束、幂等与契约检查。不能简单允许任意200/501，也不能删失败用例冒充通过。
2. 能力注册：每个领域有自己维护的已验收接口编号集合，composition集中汇总，runtime如实展示；公共system.py不由三人轮流修改。AI provider状态同理由C贡献实际值。
3. 请求事务：为AI入口提供无长期写事务的鉴权上下文，后续写事务重新验权；其余短写沿用既有UoW。Clock和Settings能一致传给服务，不让FakeClock与服务中的真实时钟混用。
4. 最小内部port补齐：至少覆盖Profile读取、当日任务读取、通知事件处理、提案明确决策、受控媒体字节读取和生成音频登记。复用既有DTO，写入准确参数、返回值、事务和文件I/O约定。
5. 媒体鉴权：明确MEDIA03的Bearer或短ticket路径。生成音频通过MediaPort登记；C不直接操作A媒体表或猜文件路径。
6. 组装：业务服务的可注入时钟、配置与ports只在composition连接。保留现有ServiceBundle字段含义，避免循环依赖，不增加通用RPC/插件平台。

A0可以修改公共文件，但要同步schema/快照（确有公开变化才更新）、文档和测试。新入口先允许明确501占位，A/B/C按任务单各自实现；A0交接必须说明哪个入口仍是占位。只有纯内部port变化时不要重写无变化的OpenAPI。
