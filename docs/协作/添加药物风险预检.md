## 行为

老人、子女用药编辑页首先调用 PLAN05 检查，展示结果后第二次明确点击才保存计划/提交申请。字段或老人变化后旧结果失效；可重新检查。子女仍走 CHANGE01，预检不赋予直接写计划权限。模型失败、未配置或资料不足都不能显示为“没有风险”；不会自动停药、改药或生成服药记录。允许用户在核对已有医嘱后继续保存，风险检查不是医疗开方或硬性拦截。

PLAN05：POST /api/v1/elders/{elder_id}/medication-plan-risk；请求 MedicationRiskCheckWrite（plan 必填，替换时 replace_plan_id/expected_version 成对），响应 MedicationRiskCheckResult（status、findings、model、checked_at）。本人和已绑定子女可读预检；401/403/404/409/422 维持真实权限、资源与版本语义。该只读预检不保存拟新增计划、修改申请、服药记录或当日异常。

模型输入包含拟提交药物、现有真实用药和版本化的已确认档案（出生日期、疾病、过敏、医疗备注）。替换时排除原计划，避免自己与自己比较；活动的未来计划带起止日期交模型区分。使用已有 CHAT_* 的 MiMo，不引入本地医疗冲突表。新 MedicationRiskReviewer typed Protocol 由同一个 MiMoReportWriter 实现；预检仅输出结构化风险，不生成六段日报文字，减少延迟。纯模型调用在全部 UoW 之外；结束后重新认证与比较快照摘要，期间资料变动返回409要求重查。格式/证据最多一次修正，仍共用20秒预算。

SafetyFinding 新增 drug_profile（药物与档案疾病/过敏风险线索）；该类结果必须有 profile 和 medication 两种合法来源，所有引用逐条校验。SafetyEvidence 增加 profile 与 proposed_plan；后者明确为未保存草稿、不能冒充实际资源/服用事实。日报的实际生效药物复核只用真实来源并保存；PLAN02/03 保存后也自动安排既有日报复核（SAFETY_REVIEW_ENABLED=true），沿用两端日报顶端、日历与子女弹窗。后台模型异常不会把已保存计划说成保存失败，用户可再核对。
