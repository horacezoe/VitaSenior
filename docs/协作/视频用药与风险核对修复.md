## 提醒时间实际含义

固定时间按 UTC+8，单进程扫描每 5 秒创建待处理提醒，前台约 20 秒刷新可见；扫描和提醒播放不产生服药记录。餐后安排等待对应餐食打卡，due_at=餐食 occurred_at+delay_minutes；缺少该餐记录时 waiting_for_meal=true，不猜吃饭时间。不回填已过去的新增义务，不因未记录就认定未服药。

## 2026-11-01 追加：提醒时点不再限制实际服药打卡

用户截图原句“呃，吃完之后，我吃了降压药”，旧对话因 `due_at > occurred_at` 拒绝。后端 CheckinPort 本身并无此限制，断点是 C 的任务筛选。现移除 `due_at <= occurred_at` 与 `not waiting_for_meal` 的选择条件，保留当日、本人、计划/slot 版本、实际时间不能在未来、明确确认、幂等、撤销与过期等校验。不修改既定用药安排、不修改提醒时点，也不根据服药自动伪造餐食。

- 提前已服、餐后倒计时中、没有餐食打卡：均可准备 record_medication，确认后按服务端记录的实际时间保存。
- 同药多次或多药不猜目标；列出计划中的钟点/餐次供核对，私有草稿保留已选药名，下一句“晚上那次”或“午餐那次”能续接。不会只因另一条任务已到时就擅自选它。
- 确认写入后，复用 B 的 task completion 与 sync_task_notices；后续扫描即使超过原定提醒时刻、或之后补餐食记录，也不再产生该次待服药提醒。
- 用 Pydantic 私有字段补充 slot 描述，无公共 schema/表/API 契约变更。真实来源依然 agent_confirmed，不输出假的 200 或跳过鉴权。

新增回归覆盖截图原句在固定时间前/餐后未记餐/餐后倒计时三种情况的完整“准备→确认→重复确认→推进时钟→扫描”及日报验证；补充同药早晚追问与未记餐时的餐次追问。测试只用临时库和 FakeClock，不操作预览健康数据。
