| 顺序 | 工作项 | 依赖 | 完成标准 |

| B4 | 通知模型、可见心跳、事件回执、亲情提醒 | A 鉴权与媒体 | 查询不算送达；子女不能代回执；重复事件不重复触发 |
| B5 | 扫描器、到期提醒、餐后联动、重启补偿 | B2/B4；A 的 apply_due | 数据库去重；只启动一个扫描循环；关闭网页仍保留待办 |
| B6 | 与 A 联调修改通知窗口；与 C 联调打卡工具 | A6/C 的动作执行 | playback_completed 与倒计时写入同事务；Agent 确认走同一打卡服务 |

## 6. 模块间交接物

| 提供者 → 使用者 | 最迟何时 | 交接物 | 验收动作 |
| --- | --- | --- | --- |
| 框架开发者 → A/B/C | F0_READY后 | 真实的Actor、UoW、访问校验、幂等/时钟、模型/schema、全部ports与占位、基线提交 | 基础验收通过，未实现能力明确501 |
| B → A | F2首轮闭环前 | 已实现的MedicationService.import_draft、NotificationService.enqueue，沿用冻结签名 | A 建档/提案调用得到实际落库结果 |
| A → B | 第一轮闭环前 | ChangeService.mark_played / apply_due 与事务约定 | B 的回执能设置真实截止时间 |
| B → C | 第一轮闭环前 | CheckinService、ReportService、task_id 与通知事件对象 | C 的确认结果在 B 查询里可见 |
| C → A/B | 第一轮闭环前 | MemoryService.on_source_changed 与 source_ref 格式 | 纠正来源时旧归纳失效；事务内不发外部请求 |
| C → A | 第一轮闭环前 | mock 音频、场景、记忆 fixture | seed 命令可装载可演示素材 |

服务契约详细签名见接口说明第 3 节。共享 schema 发生变化时，当轮立刻修改文档与两侧代码，不在联调时临时加第二套字段兼容层。

框架完成后还需登记真实 import 路径和类型签名；业务 Agent 不根据这里的简写再发明一套。跨领域实现依赖通过 port 注入，不直接导入对方 service 类。

## 9. Git 和变更安排

- F0建立并验收统一基线；F1记录基线提交后，三人从同一提交分别创建 `backend/platform`、`backend/health`、`backend/agent` 分支。合并单位是可调用的一小组接口，不等整包完成。
- models/schema/contracts为共享冻结定义，不再由B/C各自改结构；各人维护自己的业务flow/router/service/test/fixture。A统一处理模型和契约变化，实际路径以正式任务单为准。
- 此期使用版本化的初始化 schema 与 seed；不引入复杂迁移流程。共享 schema 修改先同步；已有运行数据不默认删除重建。
- 本地数据库、上传文件、实际密钥不进入版本库；fixture 只放虚构数据。清理某次观众体验使用显式 demo_id 的管理命令，不提供公开“清空所有数据”接口。

## 10. 不足三人或时间不足时

- 只剩两人：A 继续平台/提案，B 合并健康与 C 的 mock Agent；真实供应商适配和系统推送延后。
- T−16h 仍未通主线：暂停新功能；三人一起修复“登录→绑定→Agent 确认→记录→子女看板”，随后补离线与提案窗口。
- 系统通知、真实 ASR/TTS、商城、积分、图表增强均不能挤占最后两小时演练。
- 若最终仍使用 mock，运行状态与路演讲述明确说明模拟范围；已真实落库的业务闭环可以独立展示。
