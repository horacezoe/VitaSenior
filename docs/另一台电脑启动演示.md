# A、B 协作者在另一台电脑启动演示

更新：2026-11-01。前后端都在 `codex/frontend-mobile` 分支。建议在独立目录准备演示，保留各自原开发目录与运行数据。

## 数据库是否需要迁移

- 新电脑或新的 DATA_DIR：不需要迁移。后端启动时建立当前表结构并写入13份社区样本；通过 DEMO01 分配该机器的演示家庭账号。
- 同一套新表结构下的旧演示库：可以继续使用，但旧社区内容和既有档案会保留。需要新药品样本时，选择新 DATA_DIR，或备份后显式运行样例升级工具。
- 早期F0/F1数据库缺列、启动报 DATABASE_SCHEMA_OUTDATED：样例升级工具不能补齐旧表结构。演示请使用新的 DATA_DIR。
- 需要完全复现另一台机器的账号、绑定、记录与媒体：在来源服务停止后完整复制 DATA_DIR，再配置目标机路径。Git只同步代码，不同步SQLite、媒体或私有.env；不要直接复制一个仍在写入的SQLite主文件。

两台机器使用相同代码版本和配置可展示相同样本人物，但独立生成的手机号、资源ID和会话不同。操作手册中现有手机号只对应原演示机的数据库。

## 1. 获取代码与依赖

环境：Python 3.11–3.13；项目已验证的前端环境为Node 24 / npm 11。以下为Windows PowerShell命令。

```powershell
git clone --branch codex/frontend-mobile https://github.com/horacezoe/VitaSenior.git VitaSenior-demo
cd VitaSenior-demo
git rev-parse HEAD

cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
Copy-Item .env.mimo.example .env
```

两位协作者核对 `git rev-parse HEAD` 相同。后续更新这个独立演示目录时，先检查 `git status`；工作区干净后使用 `git pull --ff-only`，不要覆盖原开发目录的未提交改动。

## 2. 配置并启动后端

编辑 `backend/.env`。A可用 `data/demo-A-20261101`，B可用 `data/demo-B-20261101`。选择一个尚未使用的目录，数据库和媒体会自动创建在里面。

```dotenv
DATA_DIR=data/demo-A-20261101
DATABASE_URL=
PUBLIC_BASE_URL=http://127.0.0.1:8000
CORS_ORIGINS=http://localhost:5175,http://127.0.0.1:5175
SCANNER_ENABLED=true
SAFETY_REVIEW_ENABLED=true
```

`DATABASE_URL` 留空可避免继承其他数据库路径。将 MEDIA_TICKET_SECRET 换成本机随机值（至少16字符），保留 APP_TIMEZONE=Asia/Hong_Kong。

页面、建档与接口联调可以先使用模板中的mock配置。现场展示真实语音、照片理解与模型风险预检时，将 CHAT_PROVIDER、ASR_PROVIDER、TTS_PROVIDER 设为 real，并分别填写自己的 CHAT_API_KEY、ASR_API_KEY、TTS_API_KEY；模型地址、型号和音色沿用 `.env.mimo.example`，确认账号具有相应模型权限。mock音频只覆盖预置样例，不能代替任意真人语音。

`.env` 不会被应用自动读取。使用仓库启动脚本加载它：

```powershell
# 当前目录：VitaSenior-demo/backend
.\run-demo.ps1 -Port 8000
```

保持该终端运行。另开终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
```

应看到 database=ok；启用扫描器后 scheduler=running。完整提醒和提案计时需要扫描器开启。

## 3. 配置并启动前端

另开终端进入同一代码副本的 frontend 目录：

```powershell
cd VitaSenior-demo/frontend
npm.cmd ci
Copy-Item .env.example .env.local
```

确认 `.env.local` 包含：

```dotenv
BACKEND_URL=http://127.0.0.1:8000
```

```powershell
npm.cmd run dev -- --port 5175 --strictPort
```

浏览器访问 `http://localhost:5175`。可以访问 `http://localhost:5175/api/v1/health` 检查前端代理。模型密钥只放后端。若后端换端口，前端 BACKEND_URL 同步修改并重启Vite。

## 4. 准备该机器的演示账号

新库启动后只有社区源样本，尚未分配展示用账号。产品登录页不展示创建家庭或人物选择按钮，讲解者在终端准备。

以下请求只创建一组独立账号和未确认的老人档案，不自动建立亲属绑定：

```powershell
$api = 'http://127.0.0.1:8000/api/v1'
$persona = 'community_sample_001'
$demoKey = [guid]::NewGuid().ToString()
$family = (Invoke-RestMethod -Method Post -Uri "$api/demo/experiences" `
  -ContentType 'application/json' `
  -Headers @{'Idempotency-Key'=$demoKey} `
  -Body (@{persona_id=$persona} | ConvertTo-Json)).data

"人物：$($family.persona_name)"
"老人手机号：$($family.elder_account.phone)"
"子女手机号：$($family.child_account.phone)"
```

保存本次输出的两个号码。请求响应丢失时可沿用同一个 demoKey 重试，避免重复创建家庭。人物目录为 `GET /api/v1/demo/personas`；`community_sample_001` 是陈阿姨，`community_sample_010` 是何伯伯，`community_sample_013` 无长期用药，`community_unmatched` 用于手工建档。为另一人物另建家庭时，修改 persona 并生成新的 demoKey。

登录与演示顺序：

1. 在 `http://localhost:5175/login` 选择“我自己使用”，输入刚生成的老人号码，获取验证码，输入123456登录。
2. 首次登录自动匹配社区档案；本人核对疾病、过敏与用药后确认保存。14天历史在此时导入，不是在刚启动后端或创建家庭时导入。
3. 老人到“设置 → 家庭连接”生成四位绑定码。子女用刚生成的子女号码、角色和123456登录，预览并确认绑定；绑定码5分钟有效。
4. 子女查看日报和日历；老人体验通话与记录。完成打卡、提醒播报和明确服药确认是不同动作。

`app.seed --mode framework` 生成的199号段账号用于框架测试，没有这些社区身份映射，不能代替上述演示家庭准备。操作手册中的原170号段号码也不会自动出现在新电脑。

## 5. 可选：保留旧演示库并升级样本内容

只在确实需要保留旧家庭/记录时执行。停止这份演示库对应的后端，确认旧路径，然后完整备份旧DATA_DIR：

```powershell
# 当前目录：backend。将 old-demo 替换为该机器实际使用的目录。
$oldData = (Resolve-Path .\data\old-demo).Path
$backupData = "$oldData-backup-$((Get-Date).ToString('yyyyMMdd-HHmmss'))"
Copy-Item -LiteralPath $oldData -Destination $backupData -Recurse

# 预演：退出时回滚，不保存业务变更
.\.venv\Scripts\python.exe -m app.tools.upgrade_sample_medications --data-dir $oldData

# 核对预演计数后，显式提交样本升级
.\.venv\Scripts\python.exe -m app.tools.upgrade_sample_medications --data-dir $oldData --apply
```

该工具只升级匹配旧默认值的样本。已确认计划还需匹配可验证的合成历史来源与起止日期；有实际打卡、修改/取消记录、图片、版本变化或无法证明来源的计划会保留。升级不会替用户改回自定义信息。完成后以相同DATA_DIR重启后端，重新打开建档页获取新草稿；旧页的草稿ID/版本可能已失效。

## 6. 手机与完全相同的演示数据

先在目标电脑的localhost验证完整流程。手机需要可互通网络和浏览器认可的HTTPS来源，摄像头/麦克风权限在手机上重新授权；局域网HTTP能打开页面，不等于能采集音视频。可信证书路径可配置在前端.env.local中，沿用前端README的HTTPS说明。

如果要求A、B两台具有完全相同的账号、绑定和历史，停止来源后端后复制整个DATA_DIR（包括数据库及媒体），使用相同代码启动目标副本，再正常登录。若原来使用外部DATABASE_URL，还要一致性备份它实际指向的数据库。私有.env、模型凭据和本地浏览器会话分别配置，不通过Git分发。
